# astrbot_plugin_auto_image

AstrBot 插件：**LLM 自主生图 / 改图**。bot 在对话中根据上下文自主决定生成或修改图片，无需记忆指令；生图参数（模型 / 画面比例 / 清晰度）支持**关键词模糊匹配**。API 后端为 Grsai，与 [astrbot_plugin_grsai_image](https://github.com/llm-astr/astrbot_plugin_grsai_image) 同一接口。

## 功能

- **LLM 自主调用**：注册 `auto_text_to_image`（文生图）与 `auto_image_edit`（图生图/改图）两个 LLM 函数工具，对话中说到「画一张…」「把这张图改成…」时 bot 自动调用并发送图片
- **关键词模糊匹配**：模型、比例、清晰度均可中文/英文模糊指定（见下表），匹配不到自动回退插件默认配置
- **改图自动取图**：自动使用当前消息图片、回复引用的图片、或会话中最近 10 分钟内发送的图片作为原图
- **按语义取图**：支持「我发的 3 张图」「某某（QQ昵称）发的 2 张图」这类说法，自动按发送人+张数挑选参考图，图片顺序按发送时间排列（最早发的为第一张）；「把我发的图1改成图2的风格」这类**序数引用**会自动识别需要的张数
- **缓存抗重载**：会话图片缓存的索引与图片副本均落盘保存，插件热重载（保存配置 / 面板重载 / 更新插件）甚至 AstrBot 重启后，缓存期内的参考图依然可用
- **预设系统**（可扩展，见 `presets.py`，各预设独立开关；多个预设同时命中时参考图按预设顺序合并，并在提示词中按**全局序数**强调「第几张是什么」）：
  - **预设① @某人头像参考图**（`preset_avatar_ref`，默认开）：消息包含「用他画 / 用她画 / 用它画 / 用他做 / 用她做 / 用它做」且 @ 了某人时，自动提取第一个被@者（非 bot 自己）的 QQ 头像作为默认参考图，再按后续要求生图，例如「@小明 用他画一个 Q 版表情包」
  - **预设② 提示词图库**（`preset_prompt_gallery`，默认开）：为图库图片绑定预设提示词；生图 / 改图要求中提到这些词时，自动把对应图片作为参考图（排在参考图最前），并在提示词中按序数强调「第 N 张是预设提示词『xx』对应的参考图」，同时声明**图中形象特征一律以参考图为准、不按文字描述另行创作**
  - **人物特征描述拦截**（`preset_gallery_strip_features`，默认开）：预设②命中时，自动移除 LLM 提示词中的人物外观描述子句（发色 / 瞳色 / 耳尾 / 面部 / 服饰 / 体型，含英文 tag），解决生图模型「文字权重高于参考图」导致的跑偏；含「改成 / 换成 / 穿上 / 加上 / 去掉」等**改动意图**的子句会保留（「把猫娘换成婚纱」这类需求不受影响）；`/生图` `/改图` 指令中用户手写的提示词不拦截
- **插件页面（WebUI）**：插件详情页提供「提示词图库」管理页面，可视化上传图片、绑定 / 修改预设提示词、删除条目（基于 AstrBot 插件 Pages，需要较新版本 AstrBot；老版本自动降级，可用 `/图库` 系列指令管理）
- **图库指令**：`/图库`（列表）、`/图库添加 <预设提示词>`（带图或回复图）、`/图库删除 <序号>`
- **表情包引用**：图片表情/贴纸自动作为参考图；QQ 收藏/商城表情（mface 消息段）适配层不会转换，插件会从原始消息中兜底提取其图片 URL；QQ 小黄脸表情转为提示词文本参与创作
- **GIF 参考图处理**：默认提取 GIF 首帧转 PNG（兼容性最好）；可切换 `direct` 模式直接传 GIF 原图自行测试
- **开始提示可切换**：默认为插件固定提示语（`fixed`），可切换为 `llm` 模式由 bot 以正常回话的方式表达「开始生成图片」
- **可配置等待时间**：识别到生图意图后可等待 N 秒再开始，用于接收用户随后发送的参考图，防止遗漏
- **低延迟优化**：开始提示在参考图下载之前发出，多张参考图并行下载转码，减少「发消息 → 开始生成」的间隔
- **失败自动切换（可选）**：开启 `auto_fallback` 后，生成失败按 `fallback_models` 列表顺序自动切换备选模型重试，列表可自由增减、调整顺序（仅限可用模型）
- **指令兜底**：保留 `/生图`、`/改图`、`/生图模型` 指令用于精确控制
- 平台图链（QQ 等多媒体链接）统一转 base64 data URL 再提交，避免 API 拉取失败

## 使用示例

### LLM 自主模式（无需指令）

```
用户：给我画一只在月球上喝茶的橘猫，横版 4K
bot ：🎨 已收到生图请求（nano-banana-fast / 16:9 / 4K），提交生成中请稍候……
      [图片]

用户：（发一张自拍）帮我改成吉卜力风格
bot ：🎨 已收到生图请求（nano-banana-fast / auto / 1K，参考图 1 张），提交生成中请稍候……
      [图片]

用户：（此前发过 3 张图）把我发的 3 张图合成一张海报
bot ：自动取该用户最近 3 张图（按发送时间升序）作为参考图生成

用户：把小红发的 2 张图拼到一起
bot ：自动取昵称「小红」最近 2 张图作为参考图生成

用户：@小明 用他画一个 Q 版表情包
bot ：自动提取小明的 QQ 头像作为参考图生成（预设①）

（图库中已有绑定「猫娘」的图片）
用户：给我画一个猫娘在海边看日落
bot ：自动携带「猫娘」图库图片作参考图，提示词中强调第 1 张是「猫娘」预设参考图、形象以图为准（预设②）
```

> 当 `progress_msg_mode=llm` 时，插件不发送固定提示，「开始生成」由 bot 用正常回话表达（是否先说一句取决于所用模型的回复习惯）；`wait_before_generate` 大于 0 时会先等待相应秒数收集参考图，再提交生成。

### 指令模式

```
/生图 一只在月球上喝茶的橘猫 横版 4K pro
/生图 赛博朋克城市夜景 -m nano-banana-pro -ar 21:9 -s 4K
（回复一张图片）/生图 把背景换成海边
/改图 改成水彩画风格 高清
/改图 把我发的2张图合成一张
/生图模型
/图库添加 猫娘 女仆装   （消息里同时带一张图，或回复一张图）
/图库                  （查看图库列表与图片）
/图库删除 1            （序号为 /图库 列表中的编号）
```

### 提示词图库（预设②）

- **WebUI 管理（推荐）**：WebUI → 插件管理 → 点击本插件卡片进入详情页 → 打开「提示词图库」页面，可上传图片、绑定 / 修改预设提示词、删除条目（页面基于 AstrBot 插件 Pages，需要支持该能力的 AstrBot 版本；不支持时页面不显示，不影响指令管理）
- **QQ 指令管理**：`/图库添加 <预设提示词>` 并附带（或回复）一张图片；`/图库` 查看；`/图库删除 <序号>` 删除
- 图库数据保存在 AstrBot 插件数据目录（`data/plugin_data/astrbot_plugin_auto_image/prompt_gallery/`），**更新 / 重装插件不会丢失**
- 生图 / 改图要求中提到任一预设提示词时，对应图片自动排在参考图最前，且提示词中按全局序数强调「第 N 张是预设提示词『xx』对应的参考图」，并声明图中形象特征以参考图为准（不再按文字描述另行创作，避免文字描述与预设图打架）；与其他预设（如 @某人头像）同时命中时序数自动顺延
- 每张图最多 10 个预设提示词（单个 ≤30 字），图库容量 60 张，单图 ≤15MB，支持 jpg / png / webp / gif

### 模糊关键词表

| 参数 | 可用关键词（节选） |
| --- | --- |
| 模型 | fast / 快速、香蕉 / banana、pro / 专业、香蕉2 / 二代 / nb2、gpt / openai、vip / 会员 … |
| 比例 | 横版/横屏/壁纸(16:9)、竖版/竖屏/手机壁纸(9:16)、方图/头像(1:1)、电影/超宽(21:9)、小红书(3:4)、或直接写 16:9 |
| 清晰度 | 标清(1K)、高清(2K)、超清/超高清(4K)、或直接写 1K/2K/4K |

> 注：仅 nano-banana pro / 2 系列支持 1K-4K 清晰度参数，其他模型自动忽略。

## 配置

| 配置项 | 说明 | 默认 |
| --- | --- | --- |
| api_key | Grsai API Key（必填） | 空 |
| api_node | API 节点：cn / global | cn |
| model | 默认生图模型 | nano-banana-fast |
| aspect_ratio | 默认画面比例 | auto |
| image_size | 默认清晰度 | 1K |
| progress_msg_mode | 开始生成提示方式：fixed=插件固定提示语（默认）；llm=由 bot 正常回话表达 | fixed |
| wait_before_generate | 识别到生图/改图意图后、开始生成前的等待秒数（0-60），用于接收随后发送的参考图，防止遗漏；仅对话模式生效 | 0 |
| gif_handling | GIF 参考图处理：first_frame=提取首帧转 PNG（默认）；direct=直接传 GIF 原图（可自行测试 API 是否支持） | first_frame |
| auto_fallback | 生成失败时是否自动切换备选模型重试 | false |
| preset_avatar_ref | 预设①：「用他/她/它 画/做」+ @某人时自动以被@者 QQ 头像作默认参考图 | true |
| preset_prompt_gallery | 预设②提示词图库：生图/改图要求命中预设提示词时自动带图库图片作参考图并按序数强调 | true |
| preset_gallery_strip_features | 预设②命中时拦截 LLM 提示词中的人物外观描述（发色/瞳色/服饰等），让生图以参考图为准；改动意图子句保留 | true |
| fallback_models | 备选模型列表（按顺序依次切换，可自由增减，仅限可用模型；无效项自动跳过） | nano-banana-fast / nano-banana / nano-banana-pro / gpt-image-2 |
| poll_timeout | 每个模型等待生成结果的最长时间（秒） | 300 |
| poll_interval | 结果轮询间隔（秒） | 4 |

## 安装

1. 将本插件放入 AstrBot `data/plugins/` 目录，或在管理面板通过仓库地址安装
2. 安装依赖：`pip install -r requirements.txt`
3. 在插件配置中填写 Grsai API Key
4. **LLM 自主生图需要**：使用的 LLM 供应商支持函数调用（function calling），且 AstrBot 中未禁用工具调用

## 说明

- 参考图限制：最多 8 张，单张小于 10MB，多张参考图并行下载转码
- 参考图来源同时记录平台 URL 与本地文件：记录缓存时会把本地临时文件**复制到插件目录持久化**（AstrBot 的 data/temp 媒体文件可能一两分钟内即被清理、QQ 图链会过期；消息到达瞬间适配器可能尚未落盘，插件会短暂重试等待文件出现），实际取用参考图时还会再持久化一次，防止等待/排队间隙文件失效；转换时本地文件优先、失败回退 URL；两者均不可用时提示重新发图；缓存副本随缓存期（10 分钟）自动清理
- 语义取图作用于会话图片缓存（保留 10 分钟，最多 16 张/会话），**缓存索引与图片副本均落盘**（temp/cache/），插件热重载或重启后自动恢复；指定张数时取该发送人最近的 N 张，按发送时间升序（最早发的为第一张）；「第一张/第二张」这类序数说法不会被误当作张数，而「图1/图2」这类序数引用会被识别为需要最近 2 张；只指定归属（如「我发的」）未指定张数时默认取最近 4 张
- GIF 参考图：Grsai 文档未明确支持 GIF，其底层模型官方仅支持 PNG/JPEG/WEBP，故默认提取首帧转 PNG；如需实测直接传 GIF，将 `gif_handling` 改为 `direct`
- QQ 表情：图片表情/贴纸会以参考图形式提交；收藏/商城表情（mface）通过解析原始消息提取 URL；小黄脸表情（Face）无法转为图片，会改为把表情 id 以文字形式附加到提示词中
- 若消息链中的图片被其他插件剥除（例如私聊收口/视觉转述类插件把图片转成文字或中止事件传播），插件会尝试从原始消息的 image 段恢复图片 URL；若其他插件连原始消息也改写，则需调整该插件的设置（关闭单图防抖/转述）
- 插件每次记录到会话图片时会输出日志 `[auto-image] 记录会话图片 N 张`，若改图时提示找不到图片，可先检查日志确认图片是否被插件看到
- 开启自动切换后，每次切换会在 fixed 模式下提示「🔁 模型 X 生成失败，切换 Y 重试」；清晰度（1K/2K/4K）参数仅在支持它的备选模型上携带；注意每个备选模型都会各自计时 poll_timeout
- 「发消息 → bot 开始生成」的间隔主要来自 LLM 决策（理解对话并发起工具调用），这部分由所用模型决定；插件侧的等待（参考图下载转码）已移至提示消息之后并行处理
- 生成结果图片 URL 有效期约 2 小时，插件会先下载到本地再发送，发送后即删除临时文件
- 头像参考图取自 QQ 公开头像接口（q1.qlogo.cn），URL 稳定不过期；若消息同时带有明确取图语义（如「用他和我发的两张图合成」），头像会与语义挑选的图片一并作为参考图
- 提示词图库的图片为本地长期文件，不会写入会话图片缓存（避免污染「我发的图」语义取图）；图库关键词按子串包含匹配（不区分大小写），**匹配范围 = 用户消息原文 + LLM 实际生成的提示词**（措辞与关键词有出入时，LLM 扩写的提示词里通常仍包含该词），一次最多自动附加 6 张图库参考图；插件启动日志会输出图库加载数量与存储目录，生图时若图库非空但未命中会输出提示日志便于排查
